# 复杂组合路径设计

## 目标

在现有单一路径打印能力之上，增加一层“工艺步骤序列”能力，使系统能够把多个几何轨迹和非打印动作按顺序组合成一个完整打印流程，同时保留现有单一路径预览与打印能力不变。

第一版只解决以下需求：

- 复用现有 `Trajectory` / `TrajectoryFactory` 生成单个几何路径
- 支持将多个路径段和过渡动作串联成一个复杂流程
- 在可视化界面中选择预设复杂流程并预览整体路径
- 让打印线程既能执行旧的单一路径，也能执行新的复杂流程

不纳入第一版范围的内容：

- 图形化拖拽式流程编辑器
- 用户在界面中自由新增任意步骤
- 通用脚本语言或 DSL
- 多喷头、多材料、分支流程

## 现状

当前代码结构中：

- `控制代码/Trajectory.py` 负责几何段、采样点和预置轨迹工厂
- `可视化(1)/MINE_window.py` 负责参数收集、路径预览和打印执行
- 打印逻辑默认假设“本次任务只有一条轨迹”

这导致系统可以执行单个矩形、圆、弦图、直线，但不适合表达：

- 区域 A 打印后移动到区域 B 再打印
- 打印段之间插入抬高、回抽、空走
- 一次任务里执行多种不同轨迹

## 方案概览

第一版采用“几何层 + 工艺层 + 执行层”三层结构：

1. 几何层继续保留 `Trajectory` / `TrajectoryFactory`
2. 新增一个轻量的工艺流程对象 `PathProgram`
3. 打印线程增加对 `PathProgram` 的执行能力

这样做的原因：

- 保留现有轨迹生成逻辑，避免重写成熟代码
- 把“几何形状”与“打印步骤”分离，减少后续耦合
- 后续如果要增加界面式流程编辑，仍然可以复用 `PathProgram`

## 数据结构

新增文件：`控制代码/PathProgram.py`

建议定义两个核心对象：

### ProgramStep

表示一个工艺步骤，至少包含：

- `step_type`
- `name`
- `params`

第一版支持四类步骤：

1. `travel`
   - 机械臂移动到指定点
   - 喷头关闭

2. `print_trajectory`
   - 执行一个 `Trajectory`
   - 使用当前打印参数或步骤级别参数进行预挤出、持续挤出、停喷、回抽

3. `lift`
   - 在当前位置基础上仅调整 `z`

4. `retract`
   - 单独执行一次回抽

### PathProgram

表示一个完整复杂流程，包含：

- `name`
- `steps`

并提供简单的构建方法，例如：

- `add_travel(point_xyz, name=None)`
- `add_print_trajectory(traj, name=None, ext_rpm=None, prime=None, retract=None)`
- `add_lift(delta_z, name=None)`
- `add_retract(pulses, speed=50, name=None)`

## 文件职责

### `控制代码/Trajectory.py`

保持现有职责，不加入复杂工艺控制逻辑：

- 负责几何段和路径点生成
- 继续提供 `TrajectoryFactory.circle/rectangle/rectangle_outline/line/chord_diagram`

### `控制代码/PathProgram.py`

新增，负责：

- 定义 `ProgramStep`
- 定义 `PathProgram`
- 提供复杂流程预设构建函数

例如第一版可预置：

- `build_dual_region_program()`
- `build_rect_circle_program()`
- `build_multi_line_program()`

### `可视化(1)/MINE_window.py`

扩展现有逻辑：

- 增加“单一路径 / 复杂流程”的模式入口
- 预览时能够把 `PathProgram` 展开成一条总路径并绘图
- 打印时根据输入对象类型选择：
  - 执行单一路径
  - 执行复杂流程

## 执行规则

打印线程执行 `PathProgram` 时，逐步处理：

### `travel`

- 停止喷头
- 机械臂移动到目标点

### `print_trajectory`

- 获取轨迹点列
- 移动到该轨迹起点
- 预挤出
- 开启持续出料
- 执行轨迹
- 停喷
- 回抽

### `lift`

- 读取当前 TCP
- 只修改 `z`
- 移动到新的安全高度

### `retract`

- 单独执行回抽，不移动机械臂

### 中止与状态

- 任何步骤执行前后都检查 `_abort`
- `Esc` 急停继续复用现有逻辑
- 打印过程中继续避免 UI 主线程并发访问喷头串口

## 预览规则

第一版预览只追求“路径可见、顺序正确”，不在界面上展示全部工艺细节。

具体做法：

- 对 `travel`、`lift`、`print_trajectory` 展开成 3D 点列
- 统一映射为预览折线
- 打印段与非打印段可使用不同颜色或线型区分

如果第一版想控制改动范围，也可以先统一用一条折线显示总路径，仅在日志中标出步骤名称。

## UI 范围

第一版不做步骤编辑器，只做“选择预设流程”：

- 保留现有单一路径选择
- 新增复杂流程预设选择入口
- 用户可在预设之间切换、预览、执行

这样能够最快验证流程层是否工作，并且不会让当前窗口结构大幅膨胀。

## 风险与控制

### 风险 1：`MINE_window.py` 继续膨胀

控制方式：

- 尽量把复杂流程构建逻辑放进 `PathProgram.py`
- 打印线程只负责执行，不负责定义预设内容

### 风险 2：喷头和机械臂控制耦合继续加深

控制方式：

- `print_trajectory` 的喷头启停逻辑单独抽成内部辅助函数
- `travel` / `lift` 明确不触发出料

### 风险 3：预览与实际执行不一致

控制方式：

- 预览和执行尽量共用同一份展开后的路径点
- 非打印段至少在日志中明确输出

## 第一版验收标准

满足以下条件即可视为第一版完成：

1. 保留现有单一路径打印功能
2. 新增至少一种复杂流程预设
3. 能在界面中预览复杂流程总路径
4. 能顺序执行复杂流程中的多个步骤
5. 复杂流程步骤之间可包含空走、抬高或回抽
6. 急停、连接复用、喷头串口并发保护不退化
